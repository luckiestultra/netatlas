# Upstream integration batch

Scope authorized by the user: bring useful content from maintained GitHub projects into the existing client-first repository, with independent multi-agent red/blue verification. Existing native-app limitations remain explicit. No new commit/push authorization is inferred from research alone.

## Acceptance criteria

- Expand the portable application catalog by 23 reviewed DLC services, preserving the previous 15 source files byte-for-byte. Specialized Apple TV, Copilot and npm routes must precede parent lists in actual native proxy behavior.
- Reject URL-shaped domain input before IDNA conversion. Invalid upstream input must abort the whole sync without changing previous source or metadata.
- Reject symlinked managed ancestors before source publication or generated-cache writes. Independent negative fixtures must prove external file trees remain unchanged.
- Admit a maintained, explicitly MIT-licensed anti-AD source only after checking the exact pinned data and license. Keep a large optional ruleset out of default inline profiles while exporting usable standalone rules for all eight clients.
- Add a small, explicitly licensed HTTP-to-HTTPS rewrite projection with complete source and notices. Exclude downgrade, unrelated regional changes, dynamic code and storage APIs. Do not mislabel GPL-derived files as MIT.
- Document rejected or deferred packages: stars and a root SPDX identifier are insufficient if bundled dependencies or corresponding source are incomplete.
- Preserve deterministic offline builds, source/license hashes, native path types and honest validation levels. Native modules, rewrite resources and manually merged fragments remain distinct.

## Verification

1. Red reviewer independently attacks existing input, filesystem and native contracts; no implementation reasoning is supplied as a conclusion.
2. Blue reviewer independently constructs reproductions, verifies effects on old data and external files, then repeats the same cases after fixes.
3. Regression tests fail before each behavioral fix. Unit/parser success is not reported as native-app execution.
4. Build all clients and validate actual generated artifacts. Run fixed Mihomo/sing-box checks, compile rule sets, and run HTTP/SOCKS fixture routing with upstream-connection evidence.
5. New third-party resources need original repository, exact commit, license, source hash, dependency review, transformation notes and client-specific install instructions.
6. The user selected independent Agent red/blue review; no external-model CLI is invoked.

# 验证记录

本记录对应 2026-10-31 的实现与本地验证。已验证的行为与仍需设备验证的部分分别列出；远程 CI 的实际结果见 [GitHub Actions](https://github.com/luckiestultra/netatlas/actions/workflows/ci.yml)，不能由本地测试推断。

## 数据、构建与语义

- 15 组规范规则，共 5,077 条。上游固定为 `v2fly/domain-list-community@1daade8c4bb957d21d1f5c09c2b050d699e8e96c`，许可 MIT；许可与每个输入文件的 SHA-256 均登记。
- 真实固定版同步 dry-run 获取 214 个文件、209,250 字节，结果 `changed:false`。这是选定列表和显式 include 的可移植投影，九次正则排除逐条登记；不包含全仓 affiliation 聚合。
- 八客户端均生成原生主配置和全部 15 组独立规则。规范化、域名边界、IPv4/IPv6、转换往返、策略引用、规则先后关系均有回归检查。
- 完整数据上的 OpenAI、Claude、Gemini、YouTube、GitHub、Netflix、Telegram、Apple、China、广告、本地网络和未列出目标的预期策略逐一通过八种原生文本解析后的检查。
- 相同输入两次生成相同字节。源文件校验值不一致、构建期间输入改变、生成文件或清单被手工修改时均阻止发布。旧产物批次移入忽略的 `.cache/build/` 保留；构建不会永久清除旧树。
- 独立审查发现并修复了根清单手改保护、输入快照一致性两处问题；用临时副本重现和复核修复，策略顺序反转也能被回归测试捕获。

## 原生内核与应用

固定内核为 Mihomo 1.19.33、sing-box 1.14.4。下载来源与压缩包 SHA-256 在 [native-tools.json](../metadata/native-tools.json)。运行 `npm run test:native` 会校验二进制、检查完整配置、编译 sing-box 规则，并执行仅回环地址参与的真实路由测试。具体证据保存在忽略的 `.cache/native-check/latest.json` 与相邻日志，不读取或改动用户正在运行的客户端。

本轮在 macOS ARM64 实际执行通过：

| 检查 | 结果 |
| --- | --- |
| 官方压缩包 SHA-256 与二进制核对 | 两内核通过 |
| 完整 Mihomo 与 sing-box 主配置 | 两套通过 |
| sing-box 规则集编译 | 15/15 通过 |
| 真实 HTTP 与 SOCKS5 路由 | 44/44 行为用例通过 |
| 回环 HTTP 服务实际命中 | 24 次 |
| 回环 SOCKS 上游实际建立连接 | 12 次 |

路由用例覆盖明确 DIRECT、明确 REJECT、初始默认拒绝、手动默认直连、实际经过代理上游，以及后缀根域/子域与相似域的边界。仅临时测试配置改变端口、DNS 和测试上游；发布配置没有这些 fixture。报告保存检查时间、原生配置与规则输入 SHA-256 及检查副本，已确认与本轮生成目录的对应文件一致。

Linux x64 下载资产及校验值已登记，由 CI 使用相同固定版本执行验证；本地没有执行 Linux 内核，其远程执行证据以 Actions 运行记录为准。

Quantumult X、Surge、Loon、Shadowrocket、Egern、Stash 尚未在真实应用导入；其状态仍为 `manual-import-required`。八个配置的结构与引用检查不能替代这一项。构建清单中的 `native:not-run` 只描述确定性生成阶段，原生执行报告另行保存。

## CI 与发布

工作流 YAML、Action 固定 SHA、只读权限及 shell 语法已检查。用户已授权将完整内容提交并推送到 main；远程 CI 通过情况以对应提交的 Actions 运行记录为准。本轮不创建 PR、发布版本或修改用户客户端配置。手动上游工作流只产出候选差异，不自动提交。

## netatlas 更名与红蓝交叉验证

本地目录、npm 包名与 lockfile、默认公开 URL、文档、模块名称、生成清单和 Git remote 已统一为 `netatlas`，展示名称为 NetAtlas。GitHub 仓库改名为 `luckiestultra/netatlas`，仓库 ID 仍为 `1440126395`；本地原目录通过移动保留全部内容，旧批次及审计记录留在忽略的缓存中。

红方独立检查重命名、八客户端内容、规则语义、许可、同步与覆盖保护，并用临时副本移除后缀域名边界，确认现有回归会失败。蓝方独立核对 8 套主配置、120 份规则与全部清单的 SHA-256/字节长度，并检查本地 Markdown 目标与大小写。

发现一项 P2：自定义 `--base-url` 构建后，原验证器固定使用默认 URL，误报合法产物。现验证器支持同一参数，新增实际 CLI 子进程回归；红蓝双方分别复现修复后的构建、比较、全量验证与单客户端验证成功，故意错误地址仍被拒绝。双方均未发现剩余阻塞问题。

改名后重新执行两内核检查、15 个 SRS 编译、44 个真实路由用例、两个 GeoIP 实时源及固定版同步 dry-run，全部通过。当前“齐全”指八客户端基础配置与已登记分流导出；可选脚本/重写/模块仅 QX 和 Surge 有已实现适配，其他客户端能力范围见能力表。六个图形客户端仍待真实导入。

仓库更名不等于代码已发布。本地红蓝验证与远程发布验证分开：后者检查 main 的提交、公开文件字节和 CI 状态，不能用本地检查替代。
